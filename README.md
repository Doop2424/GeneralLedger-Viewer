# 원장 조회기 (SAP BKPF·BSEG 전표 분석) v1.6

감사 전표테스트를 위해 SAP 원장(BKPF·BSEG 추출 txt, FBL3N 엑셀)을 **사용자 PC의 브라우저 안에서** 조회·분석·표본추출·리드 작성하는 단일 HTML 도구입니다.

## 보안·데이터 처리 방식
- 원장 데이터는 **어디로도 전송되지 않습니다.** 브라우저가 PC의 파일을 직접 읽어 브라우저 메모리(DuckDB-WASM) 안에서 처리합니다.
- 이 저장소에는 프로그램 파일만 있습니다. 세션 파일(JSON)·스냅샷(zip)·엑셀 결과물에는 고객 원장이 포함되므로 **절대 저장소에 올리지 마십시오.** (`.gitignore`로 차단)
- 네트워크 확인: 브라우저 개발자도구 → Network 탭에서 원장 적재 중 외부 요청이 없음을 확인할 수 있습니다.

## 파일 구성
| 파일 | 용도 |
|---|---|
| `index.html` | 조회기 본체. 엔진(DuckDB-WASM 1.29.0)·SheetJS 0.18.5·fflate 0.8.2는 CDN(jsDelivr·cdnjs)에서 받음 → 인터넷 필요. GitHub Pages 주소로 열거나, 내려받아 PC에서 더블클릭해도 동작 |
| `README.md` | 이 설명 |
| `.gitignore` | 고객 데이터·산출물이 저장소에 올라가지 않도록 차단 |

CDN이 차단된 환경용 오프라인 패키지(lib 동봉, 76MB)는 별도로 보관하며 사내 웹서버에 배포합니다.

## 요구 사항
- 64비트 크롬 또는 엣지(데스크톱). 폴더 선택·자동 복원은 크롬·엣지 전용.
- 메모리: 16GB 권장. 8GB는 하이브리드 N=10, 압축 해제한 txt 사용 권장.
- 한 탭이 쓸 수 있는 메모리는 약 4GB입니다. 전체 라인 적재는 3~4개월분까지, 하이브리드 적재는 12개월 가능.

## 사용 순서
1. **원장 불러오기**: 월별 폴더 또는 zip을 끌어다 놓기. 적재 모드(전체/하이브리드), N·K, 특이 라인 조건, 적재 범위 설정.
2. **계정과목표**(SKAT 또는 코드·이름 두 열) 연결 → 계정명 검색.
3. **조회** 탭에서 조건 조회·집계·엑셀, 행 클릭으로 분개 패널(T계정·항목별 분석).
4. **시산표 대사 / 전표 차대 검증 / 전표번호 검증 / 월별 추세**로 완전성 검증.
5. **시나리오**(13종)·**시각화**(히트맵·흐름도·벤포드)·**표본추출**(무작위·MUS·층화, 시드 기록).
6. **전표 담기 → 요청 파일**(요청목록+전체분개+조서요약)로 회사에 증빙 요청. 전표별 검토 메모.
7. **자산 리드**: FBL3N·자산대장으로 유·무형자산 증감 리드(1단계 → 대장 반영 2단계).
8. **세션 저장**(설정·계정표·매핑·담은 전표·메모) + **적재 스냅샷 저장**(원장 Parquet) → 다음날 수 초 만에 복원.

## GitHub Pages 배포
1. 저장소에 `index.html`, `README.md`, `.gitignore`를 올림 (Add file → Upload files)
2. Settings → Pages → Branch: main, 폴더 `/ (root)`
3. 발급된 주소로 접속. 비공개로 운영하려면 GitHub Pro/Team의 비공개 Pages 또는 사내 서버에 같은 파일을 복사

## 주의
- 스냅샷·세션 파일은 암호화된 업무 저장소에만 보관하고 감사 종료 후 보존 정책에 따라 삭제하십시오.
- 하이브리드 적재의 "요약" 행은 계정·차대별 합계이므로 라인 단위 테스트(둥근 금액, 라인 표본)에서는 자동 제외됩니다. 필요한 전표는 분개 패널의 [원본 불러오기]로 전 라인을 확인하십시오.
